## Screenshot safety

Checked specifically, as the brief requires. **No deployment URL, bearer token, run token or phone-number-like identifier appears in any image in this package.**

The three places a credential was most likely to be on screen were each inspected:

| Surface | What it shows | Verdict |
|---|---|---|
| Fleet card overflow | today's spend, a health probe line | no credential — and the menu is clipped anyway |
| Work detail metadata line | version · provider · model · actor · timestamp · duration | no credential; the id chip is an 8-character prefix, not a token |
| Runtime log view | — | never reached |
| Deploy panel | `http://127.0.0.1:4599` | a loopback address from the local seed, not a real endpoint |
| Secrets | a passcode gate | no value rendered; the product's own rule is *names only* |

All data is local seed data on a development server. The email addresses shown (`adarsh@jaroku.dev`, `e2e@jaroku.test`, `audit-newcomer@jaroku.test`) are local test accounts.

### States reached by contrivance

Two, and both are captioned as such where they appear:

- **`AUTH-01 / expired-session`** — not contrived; it happened on its own when the relay closed an hour-old socket mid-audit.
- **`ONB-01 / ready-step-shown-to-new-user`** — reached by signing in as a fresh address *within an existing app session*. From a cold launch the flow starts correctly at step 1. The screenshot is of a defect, not of the ordinary onboarding path, and the SCREEN.md says so.
- **`CKP-07 / modal-open`** — the pre-flight gate was opened and then **cancelled**. No job was dispatched at any point in this audit.
